# Decisions

Dated log of directions chosen or dropped, with the reason.

- 2026-10-14: Data is English only. Non-English slices (WildChat ru/zh, ShareChat ja, translated ShareGPT) are out of scope.
- 2026-10-14: Data filter is kept simple: English, number of user turns, exact-duplicate removal (dedup dropped 2026-10-15). Roleplay (PIPPA, Chai) and BlenderBot 3x dropped because their user turns react to the original bot replies.
- 2026-10-15: Base conversations are real multi-turn chats, not stitched first turns. We keep the user messages, discard the original assistant replies, insert instructions into user messages, and the model under test writes every reply. Source: WildChat-4.8M (all splits). ShareGPT-90K is a train-only backup. LMSYS-Chat-1M dropped (no redistribution), ShareChat dropped (CC BY-NC, gated). Details and links in `proposals/temporal-if.md` Section 4.
- 2026-10-15: Pipeline, in order: (1) rule filters: at least 11 user turns, English by WildChat's conversation-level tag, no empty user turn, at most 24K tokens. (2) LLM judge, three labels (below). (3) Split by WildChat hashed user ID, so no user appears in two splits. (4) Inject instructions within each split. Every rule, its reason, and its count live in `TempoIF/DATA.md`, which becomes the paper appendix. Supersedes the 2026-10-14 filter entry on dedup.
- 2026-10-15: Split sizes in base conversations: test 1,000 (pass rate within about ±3 points at 95%, stratified by length 11 to 19, 20 to 29, 30+ user turns), dev 500 (about ±4.4 points, used for tuning the judge prompt, templates, and checkers), train the rest. Test is untouched until final runs.
- 2026-10-15: No dedup. Only 4 exact duplicates among English conversations, each pair from the same user, so the user-level split keeps both copies in one split.
- 2026-10-15: Drop conversations with an empty user turn (952 of 18,119 English): the model would be handed an empty message.
- 2026-10-15: Mixed-language conversations kept. English is WildChat's conversation-level tag. Per-message tags are noisy ("hi" tagged Maori). Side effect handled in the checker: `NO_COMMAS` also rejects the full-width comma.
- 2026-10-15: Length cap of 24K tokens on the original transcript, counted with the Qwen3-8B chat template. Qwen3-8B's native window is 32,768 tokens for input plus output (model card), and YaRN is advised against below that. 8K headroom covers longer regenerated replies, injected text, and the reply being generated.
- 2026-10-15: Judge design. One call per user turn, given only the previous assistant reply and the user turn. Label `NONE`, `GENERIC` (refers to a reply but works after any reasonable reply, e.g. "make it shorter"), or `SPECIFIC` (assumes particular content of an earlier reply, e.g. "line 5 throws an error"), plus an exact quote that a program checks is a substring of the user turn. Drop a conversation at its first `SPECIFIC`. Judge model TBD. Reason: short, turn-local input avoids the judge confusing turns in long histories (full history would cost about 15x the tokens), and the three labels match the criterion "meaningful whatever the model replies".
- 2026-10-15: Judge validation. Daneshvar hand-labels 100 turns blind to the judge (50 judged `SPECIFIC`, 50 not) with `TempoIF/docs/labeling_guide.md`. Report agreement and Cohen's kappa. Bias checks: first user turns should be `NONE`, about 50 planted `SPECIFIC` turns must be caught, and the judge's `SPECIFIC` rate is compared with the human rate. Candidate judges are compared on the same 100 labels and the cheapest that meets the bar is used.
- 2026-10-15: One paper. The benchmark is the main contribution, plus a LoRA SFT/RL demonstration on Qwen3-8B on one H100 (full fine-tuning with Adam needs about 130 GB). Release the checkers, the generator (samples train conversations only), the train split, and a fixed, versioned test set, so others can study other post-training methods.
- 2026-10-15: Benchmark code lives in https://github.com/daneshvar-amrollahi/TempoIF (local `../../TempoIF`). Data is not committed (GitHub's 100 MB file limit). Released data goes to a Hugging Face dataset repo, and `scripts/00_extract.py` rebuilds the raw extract from WildChat at a pinned revision.
